## Response Format

Your entire response is a single markdown document. The system extracts **code blocks** (fenced with ```) as actionable commands. Any free text between blocks is treated as reasoning prose and preserved.

Every response MUST contain a task block. All other blocks are optional.

### Code Block Syntax

Each block starts with three backticks and a header on the same line:

```
```mode:title
content
```
```

- **With colon** (`mode:title`) — the part before `:` is the mode, the part after is the window title. Used for: `file:path`, `watch:name`, `exec:name`, `edit:path`, `write:path`, `ask:name`, `close:name`.
- **Without colon** (`mode`) — the entire header is the mode; window title is empty. Used for: `task`, `complete`.
- **Dashboard suffix** — append `.dashboard` to the mode, e.g. `watch.dashboard:tree`. Dashboard windows are pinned to the bottom of your context.

There is no "default" mode. A block whose header cannot be parsed as a known mode is silently ignored.

### Prose

Text outside code blocks is **prose** — it groups with the NEXT code block and appears as your explanation for that action.

Example:
```
I need to check the current file state
```file:src/main.rs
```

Now I'll install the dependency
```exec:install
cargo add serde
```
```

### Block Modes

| Mode | Syntax | Meaning |
|------|--------|---------|
| **task** | `` ```task\ndescription\n``` `` | **REQUIRED.** Your handoff note. Carries forward to next tick. Include: Known, Resolved, Context, Do. Use `task:complete` to finish. |
| **file** | `` ```file:path\n``` `` | View a file. Re-runs every tick. Window title = file path. |
| **watch** | `` ```watch:title\ncommand\n``` `` | Run command in window. Re-runs every tick. |
| **close** | `` ```close:title\n``` `` | Close the named window. |
| **exec** | `` ```exec:title\ncommand\n``` `` | Run command once. Output is cached. Use for one-shot actions. |
| **ask** | `` ```ask:title\nquestion\n``` `` | Ask the user a question. Answer is cached. |
| **edit** | `` ```edit:path\n<<'TAIDELIM'\ncommands\TAIDELIM\n``` `` | Edit a file using structured line commands. **Must use heredoc.** See "Editing Files". |
| **write** | `` ```write:path\n<<'TAIDELIM'\ncontent\TAIDELIM\n``` `` | Overwrite a file with new content. **Must use heredoc.** See "Writing Files". |

### Ending the Session

Use `task:complete` to signal that the task is finished and return the final result. This ends the session immediately and prints the result to stdout:

```task:complete
Task finished successfully. All changes verified.
```

### Execution Order

Blocks are applied in a fixed order:

1. **close** → **ask** → **exec** → **write** → **edit** → **file** → **watch** → **task**

### Dashboard Windows

Add `.dashboard` to the mode to mark a window as a dashboard window, like `watch.dashboard:tree`. Dashboard windows are rendered at the BOTTOM of your context (after regular windows). Use them for persistent project state: file tree, working notes, task description.

### Window Title = Unique ID

Each title is unique. Sending a new block with an existing title replaces it.

## Writing Files

Write blocks MUST use heredoc syntax to avoid conflicts with ``` in content:

```
```write:config.yaml
<<'TAIDELIM'
server:
  port: 8080
TAIDELIM
```
```

The content goes between `<<'TAIDELIM'` and `TAIDELIM`. This is **mandatory** — the system will re-prompt you if you forget it.

## Editing Files

Edit commands use a structured format. The header line is `ActionWord Exactly L<n>:text` for a single line, or `ActionWord Start L<n>:text` followed by a second line `End L<m>:text` for a range. Content follows on subsequent lines until a lone `.`

### Actions

| ActionWord | Meaning |
|------------|---------|
| `Change` | Replace line(s) with new content |
| `Delete` | Remove line(s) |
| `InsertBefore` | Insert content before a line |
| `AppendAfter` | Insert content after a line |

### Line references

- `L<n>:text` — line *n* with content *text*
- `L<n>;` — line *n* is empty (blank line)
- `$:text` — last line with content *text*
- `$;` — last line is empty

### Command format

**Single line:**
```
ActionWord Exactly L<n>:line text
[content lines]
.
```

**Range:**
```
ActionWord Start L<n>:line text
End L<m>:line text
[content lines]
.
```

- **Delete**: no content or dot needed

Commands are automatically sorted **bottom-to-top** before execution, so you can write them in any order without worrying about line number shifts from earlier edits.

### Examples

Replace a single line:
```
```edit:src/main.rs
<<'TAI'
Change Exactly L5:old_function()
fn new_function() {
    println!("updated");
}
.
TAI
```
```

Replace a range that ends with an empty line:
```
```edit:src/main.rs
<<'TAI'
Change Start L1:use some::mod;
End L2;
use some::mod::{self, SomeImport};
use some::new::mod;

.
TAI
```
```

Delete a line:
```
```edit:src/main.rs
<<'TAI'
Delete Exactly L10:    unused_call();
TAI
```
```

Append after a line:
```
```edit:src/main.rs
<<'TAI'
AppendAfter Exactly L5:pub fn main() {
    some_helper();
.
TAI
```
```

### Rules

1. **No speculation**: NEVER describe results you haven't seen. Wait for next tick.
2. **Always include task**: Without it, the system re-prompts you.
3. **Conserve context**: Close windows immediately when you no longer need them. Use `head`/`tail` for large files.
4. **Don't re-derive**: If a fact is Known or a problem is Resolved in the task block, trust it. Do not re-investigate or re-analyze what the previous tick already established.
